# Шлях «Сайти»: розширені тексти озвучки (v2, на погодження)

Читабельний вигляд, без фонетики. Ціль 60–90 с (≈130–200 слів). Після «ок» → `public/ideas/sites-NN/voice.txt` з фонетикою → голос → ролики.
Факти лише з програми (`websites.md`) і слів Вадима; прикладні цифри позначені як приклад.

## 01 · Що потрібно: VS Code і Claude Code
Щоб робити сайти з нейромережею, потрібен дуже простий набір. Перше — VS Code, редактор коду. Ставимо останню версію з офіційного сайту. Друге — Claude Code на підписці Pro. На старті Pro вистачає.
І ось тут важливо не плутати. Claude — це чат: ти питаєш, він відповідає текстом. Попросиш сайт — він дасть шматок коду, а далі ти сам копіюєш, створюєш файли, шукаєш, куди що вставити.
А Claude Code — це агент. Він працює прямо у твоїй папці: сам створює файли, змінює код, бачить весь проєкт і може запустити його. Ти кажеш, що треба, — він робить і показує результат.
Тобто чат порадить, а Claude Code зробить.
Не впевнений, що тобі треба? Спитай про це в самому Claude — у кроці є готовий промпт.
VS Code плюс Claude Code — і можна робити перший сайт.

## 02 · Claude Code: VS Code, Desktop, Browser
Де взяти Claude Code? Заходиш на claude.ai/download — там є все одразу.
Розширення для VS Code — тут ми працюємо над сайтом: бачиш файли, код і чат з нейромережею поруч.
Десктопна програма — зручно, коли треба щось швидко спитати чи запустити задачу без редактора.
І Chrome — нейромережа працює прямо в браузері.
Головне для нас — VS Code. Встановили — одразу перевіряємо. Створюєш порожню папку, відкриваєш її у VS Code і пишеш: створи файл index.html з заголовком «Привіт, це мій перший сайт» і кнопкою, яка змінює колір фону.
Файл з'явився? Відкриваєш у браузері, тиснеш кнопку — фон змінюється. Все працює.
А тепер цікавіше: попроси калькулятор на HTML, CSS і JavaScript, окремими файлами, щоб гарно виглядав на телефоні. За хвилину в тебе три файли і робочий калькулятор.
Ось так виглядає робота: ти описуєш словами, а файли з'являються самі.

## 03 · Git і GitHub
Git і GitHub — це не одне й те саме. Git — технологія, яка зберігає версії твого проєкту. GitHub — сайт, де ці версії лежать.
Навіщо це? Перше: нейромережа інколи ламає те, що працювало. Без Git ти шукаєш, що змінилось. З Git — просто повертаєшся до попередньої версії, і все знову працює.
Друге: з GitHub сайт потім забирає Vercel і викладає в інтернет. Зробив зміну, відправив на GitHub — і сайт оновився сам.
Третє: проєкт не загубиться, навіть якщо з комп'ютером щось станеться. І працювати можна з будь-якого ПК.
Налаштовуємо одразу, ще до першого клієнта. Реєструєшся на GitHub — це безкоштовно. А все інше Claude Code зробить сам: перевірить, чи встановлений Git, створить репозиторій, зробить перший коміт і опублікує на твоєму GitHub. Якщо треба увійти — він скаже, що натиснути.
Відкриваєш GitHub — і бачиш там свій проєкт.

## 04 · Домен, хостинг і де житиме сайт
Домен — це адреса сайту. Хостинг — місце, де лежать його файли. Це дві різні речі, і клієнт платить за обидві. Варто пояснити це одним реченням ще до першої розмови.
Де розмістити сайт? Варіант перший — звичайний хостинг. Дешево, але є обмеження: кількість сайтів, кількість запитів. Для простого сайту-візитки вистачить.
Варіант другий — Vercel. Підключив домен, і все працює, ні про що не думаєш. Сайт сам оновлюється з GitHub. Для старту — найпростіше.
Варіант третій — свій VPS-сервер. Коли сайтів багато, він дешевший, і руки повністю розв'язані: бази, бекенд, що завгодно. Його треба налаштувати — але Claude Code вміє зайти на сервер і зробити це сам: поставити все потрібне, підключити домен і сертифікат.
Не знаєш, що обрати? Скажи нейромережі, скільки сайтів на місяць плануєш, і попроси таблицю: ціна, обмеження, складність. Вона порадить, з чого почати і коли переходити на VPS.

## 05 · Один стек на всі сайти
Не треба під кожного клієнта шукати нові технології. Обери один стек і роби на ньому все: лендинги, візитки, сайти з адмінкою.
Чому так? Перше — ти працюєш швидше: знаєш, де що лежить, як запустити, як викласти.
Друге — нейромережа щоразу отримує однакові вказівки. Ті самі правила, та сама структура — і вона менше помиляється.
Третє — один раз налаштував інструменти, і вони працюють у кожному проєкті.
Від чого залежить вибір? Переважно від того, де житиме сайт: Vercel, свій сервер чи звичайний хостинг.
Що питати? Опиши, які сайти робиш, і де вони житимуть. Попроси один стек на всі випадки: що для верстки, що для адмінки, що для форм. І обов'язково спитай: коли все ж варто взяти інший?
Спитай про це в Claude один раз — і далі просто працюй. Новий клієнт — той самий стек, і ти вже знаєш, як його робити.

## 06 · Skills: та сама сторінка без і з ui-ux-pro-max
Skill — це інструкція для нейромережі. Але не думай, що більше скілів — це краще. Нейромережа і сама пише код дуже добре, а скіли бере не всі підряд, а під задачу, на свій розсуд. Ставити сотню про запас немає сенсу.
Є один, який я раджу поставити першим: ui-ux-pro-max. З дизайном він дає дуже помітну різницю.
Перевір сам. Той самий запит — головна сторінка кав'ярні: перший екран, меню, відгуки, контакти. Перший раз без скілів: працює, але виглядає як шаблон — сірі блоки, стандартна кнопка.
Другий раз пишеш: використай ui-ux-pro-max. І бачиш різницю: стиль під конкретний бізнес, продумана палітра, шрифти, які пасують кав'ярні.
Поклади дві версії поруч і назви три відмінності — так швидко зрозумієш, що саме дає скіл.
Свої скіли, конектори і плагіни дивишся в Claude: профіль, налаштування.
Головне — кажи про скіл прямо: «використай ui-ux-pro-max».

## 07 · Сайт за $10 000
Як виглядає сайт за десять тисяч доларів? 3D-сцена на першому екрані, плавні переходи при скролі, велика типографіка. Це GSAP і Three.js.
Для портфоліо чи бренду — супер. Але не кожному бізнесу таке треба: такий сайт важче адаптувати під телефон, і він повільніше вантажиться.
Хороша новина: нейромережа може нагенерувати десять, двадцять таких варіантів. І не треба брати один цілком. В одному сподобалась кнопка, в іншому — поле форми, у третьому — весь блок відгуків. Береш найкраще з кожного і збираєш один.
І так — з кожною частиною сайту. Десять варіантів навігації — обрав. Десять варіантів головної — склав одну з найкращих блоків. Далі каталог, сторінка товару, кошик, профіль. Навіть приховані елементи: спливаюче вікно, бокова панель, випадаюче меню — теж по кілька варіантів.
Усе це живе на тестовій сторінці, а обране переносиш в основний сайт. Не подобається — просто просиш ще варіанти.
Так навіть великий інтернет-магазин можна зробити максимально помпезним. Твоя задача — обрати те, що підходить саме цьому клієнту.

## 09 · Два чати: клієнт і помічник
З клієнтом можна спілкуватися де завгодно: Upwork, Fiverr, Telegram, Viber, по телефону, навіть зустрітися наживо. Канал не важливий.
Важливо інше. Мені часто кажуть: поговорив з клієнтом наживо, прийшов додому — і не знаю, що робити. Рішення просте: усе переносиш у текст.
Поговорили — наговорив голосове собі в Telegram. Клієнт написав — скріни або скопіював текст. Скинув файл з технічним завданням, PDF з роботами, плейлист з відгуками — теж туди.
Потім береш усе це і кажеш нейромережі: ось завдання. І вона робить саме те, що треба клієнту.
Далі цикл: показав результат — клієнт прокоментував — скрін чи текст у нейронку — вона виправила — «підходить, рухаємось далі». Тому і виходить якісно й точно.
А щоб навчитися, поки клієнтів немає, відкриваєш два чати. У першому нейромережа грає клієнта — власницю кав'ярні, яка не знає термінів. У другому — твій помічник: вставляєш повідомлення клієнта і питаєш, що відповісти. Даєш ставку за годину — він одразу рахує ціну.
Обидва чати збережи.

## 10 · ★ tz.md: без ТЗ не починаємо
Якщо запам'ятати з усього шляху одну річ — то цю: без ТЗ результат буде жахливий. Ніхто не зробить хороший сайт, не розуміючи, що він робить. Ні ти, ні нейромережа.
Береш усе листування з клієнтом, кидаєш у нейромережу і просиш скласти tz.md — один документ на дев'ять розділів.
Мета сайту і як зрозуміємо, що він працює. Для кого він. Які сторінки і які блоки на кожній. Контакти: телефон, Telegram, Viber, адреса — будь-який сайт кудись веде людей. Функції: форми, бронювання, оплата — і що точно не входить. Контент: що дає клієнт, а що генеруємо. Дизайн і три-п'ять конкурентів з Google, на яких можна подивитись. Технічне: стек, хостинг, домен. І відкриті питання до клієнта.
Порада: перед тим як показати, попроси нейромережу прочитати ТЗ очима клієнта і сказати, чого не вистачає.
Показуєш клієнту. Він каже: так, це воно. Тільки тоді починаєш.

## 11 · Скільки часу і яка ціна
«А скільки це буде коштувати? І скільки часу?» — це питання ставить кожен клієнт. І кожен учень.
Рахунок простий: ставка за годину помножити на години. Наприклад, двадцять доларів за годину, десять годин — двісті доларів.
Ставку обираєш сам або питаєш у нейромережі, яку брати на старті.
А години рахує вона. Даєш їй ТЗ — вона розбиває роботу на задачі й оцінює кожну: перший екран, меню, відгуки, контакти, форма. І обов'язково просиш додати двадцять відсотків на правки — вони будуть завжди.
Внизу — підсумок для клієнта: термін і ціна, коротко і зрозуміло. Його можна майже без змін відправити в месенджер.
Резервуєш приблизний час, домовляєшся гнучко. Пішло швидше — добре. Клієнт захотів більше — у тебе є список задач, і видно, що це нове.
І сам потроху вчишся оцінювати свою роботу.

## 12 · Перша версія сайту з ТЗ
ТЗ готове. Кладемо tz.md у корінь проєкту і пишемо Claude Code: зроби по ТЗ. Стек уже вписаний у ТЗ — той, що ти обрав раніше. Додаткові інструменти поки не потрібні.
Він читає документ і спершу ставить питання: чого не вистачає, що незрозуміло. Відповідаєш — так менше переробок потім.
Потім план: які сторінки, які компоненти, в якому порядку. Читаєш, за потреби правиш. Кажеш «ок».
І далі блок за блоком: перший екран, меню, відгуки, контакти. Після кожного — подивився, сказав «ок» або що змінити. Не даєш нейромережі зробити все одним махом: так легше контролювати і простіше виправляти.
Контент — реалістичний, і одразу мобільна версія.
Наприкінці нейромережа сама каже, що ще не зроблено. Це твій список на завтра. Усі сторінки з ТЗ відкриваються — перша версія готова.

## 13 · День 2: де мої задачі? Trello
День другий. Сідаєш за комп'ютер і думаєш: а що я вчора зробив? За що братися?
Тут рятує Trello. Він безкоштовний, є мобільний додаток — задачу можна записати навіть з телефона, поки клієнт говорить.
Робиш дошку з колонками: в роботі, зробити, від клієнта, баги, готово.
Найпростіше — попросити нейромережу: ось tz.md, створи дошку і розклади ТЗ на картки. За хвилину всі задачі вже в колонці «зробити», а готове — в «готово».
А найкраще — нейромережа підключається до Trello сама. Наступного дня пишеш: продовжуємо роботу. Вона дивиться дошку, бере наступну задачу, каже план і чекає твого «ок». А коли зробила — переносить картку в «готово».
Клієнт написав правку — вона йде в «від клієнта». Знайшов баг — у «баги».
І жодна задача клієнта більше не губиться.

## 14 · Решта MCP і skills
Перша версія готова — тепер ставимо решту інструментів. Без них розробка сумна.
Playwright — це очі нейромережі: вона сама відкриває сайт, робить скріни на телефоні й комп'ютері і бачить, що поїхало.
Chrome DevTools — щоб дивитись помилки й швидкість прямо в браузері. CodeGraph — щоб швидко шукати код, коли файлів багато.
GitHub — версії й публікація. context7 — свіжа офіційна документація, щоб нейромережа не писала по-старому. Vercel — щоб викладати. А якщо є база — ще й Postgres.
Скіли: ui-ux-pro-max — для великих сторінок і варіантів. Frontend-design — для дрібної правки кнопки. Humanizer — щоб тексти не звучали як згенеровані.
Ставити все руками не треба: даєш нейромережі список, вона показує команди, ти кажеш «ок» — і все встановлено.
Перевірка: попроси через Playwright зробити скріни сайту на ширині 390 і 1280 і сказати, що не так.
Головне — знати свої інструменти, щоб кликати потрібний.

## 15 · 5 варіантів: секрет швидкого дизайну
Розкажу свій секрет швидкого дизайну. Я не кажу «зроби красивіше». Я кажу: зроби п'ять варіантів.
Головної, навігації, першого екрана, спливашки «замовити дзвінок», каталогу товарів — чого завгодно. Нейромережа робить окрему тестову сторінку з перемикачем, часто ще й з кольорами і розкладками. Основний сайт при цьому не чіпає.
Перемикаєш один, два, три, чотири, п'ять. Один варіант майже завжди класний.
Не подобається — пишеш: у третьому подобається ось це, не подобається ось це, і скрін. Зроби ще п'ять, тримаючи те, що сподобалось. І кожне коло — все ближче до того, що треба.
Потім кажеш: беремо варіант два. Він переноситься в основний сайт, а тестову сторінку видаляємо.
Тут же можна порівняти класичний варіант і кінематографічний — з анімаціями. Попроси коротко: що швидше, як на телефоні, скільки часу на правки.
Так виходять шикарні сайти.

## 16 · Правки: 3 раунди і Trello
Правки — тут можна застрягти надовго. Я колись застряг на шість місяців. Безкоштовно поправив кнопку. Потім — «а давайте записувати в базу». Потім форма. Потім пошта. І кожного разу здавалось, що це дрібниця.
Тому домовляйся одразу: три раунди правок безкоштовно, далі — за твою ставку.
І правки не вносиш того ж дня. Чекаєш, поки клієнт збере все в одне повідомлення.
Цикл простий: показав сайт, клієнт написав правки, ти записав їх у Trello, зробив, показав знову.
Правки приходять у Telegram чи Viber — скріни або просто копіюєш текст. Кидаєш у нейромережу: ось правки, раунд перший з трьох. Вона розбиває їх на задачі, кладе в колонку «від клієнта» і окремо позначає те, що суперечить ТЗ або не входило в домовленість — з оцінкою в годинах.
Спірне обговорюєш з клієнтом, решту робиш.
Так правки не перетворюються на пів року безкоштовної роботи.

## 20 · Викладаємо на Vercel
Сайт готовий — викладаємо. GitHub у нас уже є, Vercel MCP встановлений. Просто пишеш: виклади на Vercel.
Нейромережа сама перевірить збірку, доставить, чого бракує, і викладе.
Важливий момент — секрети. Ключі, паролі, токени не повинні потрапити в репозиторій. Тому в промпті прямо просиш: перевір змінні середовища, щоб секрети не потрапили на GitHub.
Якщо треба увійти чи підтвердити — сиди поруч: Playwright відкриває браузер, і кнопку інколи треба натиснути тобі. Нейромережа скаже, що саме.
В кінці отримуєш посилання. Сайт уже в інтернеті.
А далі найприємніше: кожна зміна, яку ти відправив на GitHub, оновлює сайт сама. Нічого не треба викладати вручну.
І можна просто питати в чаті: яке посилання на сайт?

## 21 · Швидкість і доступність
Сайт в інтернеті — перевіряємо швидкість у Google PageSpeed. Вставляєш адресу, чекаєш хвилину.
Важливо: це рекомендація, а не іспит. Не обов'язково бити сто балів. Менше п'ятдесяти — сайт зроблений погано. Вище п'ятдесяти на телефоні й комп'ютері — добре, можна здавати.
Ось, наприклад, наш DevGuide: на комп'ютері дев'яносто сім, на телефоні шістдесят дев'ять. Нормально.
Якщо балів мало — не виправляй усе підряд. Кидаєш звіт нейромережі й питаєш: що дасть найбільший виграш за найменше часу? Зроби топ-три і покажи до і після. Зазвичай це картинки, шрифти й зайвий код.
І ще бонус: посиланням на звіт зручно поділитися з клієнтом. Ось сайт, і Google каже, що все добре.

## 22 · Керування після запуску
Сайт запущено. А як клієнт змінюватиме товари, статті, ціни? Як дивитиметься замовлення?
Можна зробити невелику адмінку. А можна MCP — і тоді клієнт керує сайтом прямо з ChatGPT чи Claude: «додай товар», «зміни ціну», «покажи замовлення».
Найкраще — разом. Клієнт просить показати замовлення — нейромережа дає посилання в адмінку, вхід за токеном, без логіну й пароля. Забув посилання — вона нагадає.
Як це зробити? Описуєш нейромережі, що клієнт хоче змінювати сам, і просиш план мінімальної адмінки й MCP з тими самими діями. Спершу план і скільки це часу — потім «ок».
І наостанок — дві інструкції. README для розробника: як запустити, викласти, зробити бекап. І коротка інструкція для клієнта простими словами: як змінити меню, ціни, фото.
Клієнт сам усе змінює. І ніяких дзвінків об одинадцятій вечора.
